# PwA 1.1.0 发布说明

发布日期：2026-10-30

## 这个版本加了什么

新增第二个 Coopanion World：**`cortico-world-memory`（记忆检索）**。它解决的是一件和游戏无关的事——
助手「汐」的工作区里有几百篇 markdown（笔记、交接、日志），但上下文一压缩就只剩最近一段，
更早的东西得靠她**自己想起来去 grep**，想不起来就等于没有记忆。

这一版给她一套本地检索层：把工作区建成本地索引，**每次重建 system 前缀时自动捞几条相关笔记塞进去**，
再给一个 `memory_search` 按需翻旧账。纯本地、零 API 成本。

Mod 与 `cortico-world-pwa` 本版**没有功能变更**（1.0.0 的包可直接继续用）。

## 记忆检索（`cortico-world-memory`）

### 索引

- 工作区 `*.md` → `<workspace>/.index/memory.db`（SQLite + FTS5 `trigram`），中文免分词；
- 按 **mtime + size** 判断要不要重读，**sha1** 变了才重切；`fs.watch` 写文件 800ms 内跟进，
  另有 30 秒定时与检索前补扫；
- 按标题/空行切成 300–800 字的段，代码块不切，每段带文档标题与小节名；
- 跳过 `.git` / `node_modules` / `blobs` / `log` / `data` / `archive` / `tmp` 与点开头目录；
- 索引是派生物：**删了自动重建**，工作区里一个文件都不动。

### 检索

```
FTS5(trigram)  ┐
LIKE 兜底       ├─ RRF 融合 Σ1/(60+rank) ─ ×(0.55+0.95×覆盖率高) ─ ×(1+0.3×30天引用) ─ ×时间衰减
本地向量        ┘
```

- **trigram 只认逐字出现**，所以查询本身也拆成三字滑窗再 OR——不然一句自然问句什么都搜不到；
- **两字词**（`药水`）trigram 索引不到，单独走 LIKE 扫原文兜底；
- **本地向量**默认是内置哈希 n-gram（零依赖、CPU 毫秒级）；把 `worlds.memory.embedModel` 指到
  放了 `model.onnx` + `vocab.txt` 的目录、并装了 `onnxruntime-node`，就换成真 embedding。
  **不联网、不调任何云端 API。**
- 覆盖率用候选池内的 IDF 加权，`怎么`/`什么` 这类到处都是的词不再干扰排序。

### 注入

```
## 相关记忆（自动检索，可能不全）
- [[notes/pwa-run-state.md]] …这局的药水只有敏捷药水，血 47/80…（2026-10-30）
```

- 每轮 5 条，**总注入硬上限 2000 token**；
- **同一批记忆连续两轮不重复注入**，换话题才重置；
- 检索超时就不注，后台跑完下一条前缀生效——不阻塞前缀构建；
- query 取最近 2 条「人说的话」（`ok`/`嗯` 这类纯应答不算），没有新消息时退到最近改动的文件名。

### 事实条目

```yaml
---
updated: 2026-10-30
status: active          # active | unfinished | superseded | archived
supersedes: notes/old-potion-rule.md
---
```

新条目写 `supersedes`，旧条目**自动**变 `superseded`——「他改主意了」不会再变成两条互相打架的记忆。

### 工具

`memory_search`（query / k / status / maxAgeDays / path）· `memory_index`（增量重建）· `memory_status`（排错）

## 已验证

- 端到端测试 **96 项全过**（`node cortico-world-memory/test/run.mjs`），含真实工作区
  **99 篇 / 6537 段**；
- spec 验收：问「我上次说的药水还剩几瓶」→ 注入里出现 `notes/pwa-run-state.md` 对应段落，
  总注入 < 2000 token；`grep` 能找到的（`敏捷药水` / `不背单词` / `token 上限`）`memory_search` 都能找到；
- 用 Coopanion 自带的 `dryMountWorld` + `parseExtensionManifest` 校验：**0 failure / 0 warning**；
- 实测：首扫 1.7 s（含向量）、单次检索 40–90 ms、索引 43 MB、一轮注入 4–5 条 ≈ 280–530 token；
- 索引不可用时（没有 `node:sqlite` / 目录写不了）**不报错**，静默退回 grep。

## 已知限制

- 注入点在 **system 前缀**，所以是「会话开始 / 上下文交接 / 前缀重载」时刷新，不是每条消息都重搜；
  会话中间要立刻翻东西得用 `memory_search`（环境提示词里已写明「想不起细节就先搜」）；
- 默认向量层是字面重叠的近似，语义相近但用词完全不同的问法可能漏，换 ONNX 模型可改善；
- 中文两字以上的词靠 LIKE 兜底扫全表，工作区到几万篇时需要再优化（当前 6500 段约 80 ms）。

## 升级 / 安装

已有 1.0.0 的话，这一版是**附加**，不动原来的东西：

```powershell
powershell -ExecutionPolicy Bypass -File tools\link-world.ps1 -Name cortico-world-memory
node tools\enable-memory-world.mjs
# 重启 Coopanion
```

或者解压 `cortico-world-memory-1.0.0.zip` 到扩展目录。两个 World 可以同时开
（`sts2_*` 与 `memory_*` 不冲突，前缀各占一段）。详见 [记忆检索](记忆检索.md)。
