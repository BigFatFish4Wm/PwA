# PwA 1.1.1 发布说明

发布日期：2026-10-31

## 这版修什么

汐反馈：1.1.0 的提醒「推送了，但没有唤醒她」。

### 根因：world 推送用了 `debounce`，不是 `flush`

Coopanion 的事件总线（`build/cortico/src/core/bus.ts` + `core/types.ts`）定义了 5 种唤醒模式：

| trigger | 行为 |
|---|---|
| `flush` | **立即投递整批积压**（会立刻叫她） |
| `debounce` | 按安静间隙 / 最小、最大合批时间合批，**不立即唤醒** |
| `preempt` | 立即投递，并取消尚未产生外部输出的在途模型轮 |
| `interrupt` | 立即投递并停止当前轮 |
| `piggyback` | 只入队，随下一批唤醒 |

推送不带 `trigger` 时：内部事件默认 `flush`，外部事件默认 `debounce`。PwA world 之前写的是 `{ trigger: 'debounce' }`，而且没有标 `origin: 'internal'`，所以每条提醒都被合批、等安静间隙——表现就是「事件进库了，但她没被叫醒」。

对照：这台机器上其它 world 的推送全部用 `flush`（共 10 处），只有 pwa 用了 `debounce`。

### 修法

- `host.pushEvent(..., { trigger: 'flush' })`；
- 事件带 `origin: 'internal'`，与其它 world 一致；
- 其余逻辑（去重、seq 对齐、attention 判定）不变。

## 另外发现（不是这次改的）

Coopanion 的 `core.log` 里在 00:25 出现过：

```
core.loop: 硬上限强制结束本次唤醒 { round: 40 }
```

也就是说她的循环跑满 `rounds.hard = 40` 会被强制收尾。如果提醒很密集，可能连续把她拉起来又很快收尾。config 里可以调大：

```json
"rounds": { "soft": 20, "hard": 40 }
```

## 升级

- Mod 和 World 都升到 **1.1.1**（本次只改了 World 的推送模式，Mod 版本号对齐）；
- 装好后**完全退出并重开 Coopanion**（World 不热加载）。

## 验证方式

1. 重启 Coopanion，进游戏到战斗；
2. 轮到她时，Coopanion 应该立刻出现「轮到你了（第 N 回合）」，并且她的循环被唤醒；
3. 若仍不唤醒：先把 `worlds.fish`、`worlds.memory`、`worlds.telegram` 临时关掉（它们都 enabled，可能也在产生事件），只留 `worlds.pwa` 观察；再看 `Coopanion/data/logs/core.log` 里有没有 `World 已启动: pwa` 和投递水位日志。
