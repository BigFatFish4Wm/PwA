# 记忆检索（`cortico-world-memory`）

> 汐写的 [`memory-retrieval-spec-2026-10-30.md`](../memory-retrieval-spec-2026-10-30.md) 的落地实现。
> 一句话：把工作区的 markdown 建成本地索引，**每轮重建 system 前缀时自动捞 5 条相关笔记塞进去**，
> 再给一个 `memory_search` 按需翻旧账。纯本地、零 API 成本。

## 为什么

| 她的问题 | 现在的解 |
|---|---|
| 想不起来去翻：全靠自己猜关键词 grep，猜错就等于没有记忆 | 自动检索（不靠模型想起来）+ `memory_search` |
| 上下文一压缩就剩省略号：handoff 只保最近一段 | 索引管「以前写过什么」，交接后照样捞得回来 |
| 流水账多、事实少：改主意就再堆一条，检索时新旧混在一起 | frontmatter `status` + `supersedes`，被推翻的自动失效 |

**没有做**（spec 第 1 节点名不要）：不换 agent 运行时、不接云端向量库、不在每轮调外部模型做抽取。
索引里所有排序信号都是本地算的，一次检索 0 token 成本。

## 装

```powershell
powershell -ExecutionPolicy Bypass -File tools\link-world.ps1 -Name cortico-world-memory
node tools\enable-memory-world.mjs
# 然后重启 Coopanion（World 是 ESM 模块，不热更）
```

停用：`node tools\enable-memory-world.mjs --disable`，再删掉
`data\extensions\node_modules\cortico-world-memory` 这个链接。

装好后 Coopanion 会多一页「记忆检索」，两个面板：

- **索引状态**：引擎（SQLite FTS5 / grep 兜底）、向量层、索引目录、多少篇/多少段、
  上次扫描、上一轮注入哪几条、最近改过的笔记、最近常被引用的笔记；
- **试检索**：输入一句话直接看会拿到哪几段（排「为什么它想不起来」用）。

## 它怎么工作

### 索引

```
workspace/*.md ──(mtime+size 变 → 重读 → sha1 变才重切)──> <workspace>/.index/memory.db
                                                          ├─ docs     一篇一行（标题/状态/关系）
                                                          ├─ chunks   300–800 字段，带上下文小标题
                                                          ├─ docs_fts FTS5 trigram（rowid = chunk id）
                                                          └─ refs     引用流水（算 30 天内引用数）
```

- 首扫全量，之后 `fs.watch`（写文件 800ms 内）+ 每 30 秒定时 + 每次检索前按需补扫。
- 跳过 `.git`、`node_modules`、`blobs`、`log`、`data`、`archive`、`tmp` 与点开头目录。
- 索引是纯派生物：**删了自动重建**，工作区里的文件一个不动。

### 检索

```
FTS5(trigram)  ┐
LIKE 兜底       ├─ RRF 融合 Σ1/(60+rank) ─ ×(0.55+0.95×覆盖率) ─ ×(1+0.3×30天引用) ─ ×时间衰减
本地向量        ┘
```

三路各自解决一个问题：

1. **trigram 只认逐字出现**。一句自然问句（`我上次说的药水还剩几瓶`）在原文里几乎不可能整段出现，
   所以查询也要拆成三字滑窗再 OR，否则什么也搜不到。
2. **两字词索引不到**（trigram 的硬限制），`药水` 这种中文两字词的召回只能靠 LIKE 兜底扫一遍原文。
3. **字面不重合但语义近**的靠本地向量补。默认是内置的哈希 n-gram 向量（零依赖）；
   把 `worlds.memory.embedModel` 指到放了 `model.onnx` + `vocab.txt` 的目录、并装了
   `onnxruntime-node`，就换成真 embedding（bge-small-zh / multilingual-e5 都行）。**不联网。**

最后的**覆盖率**用候选池里的 IDF 加权：`怎么`、`什么` 这种到处都是的二元组几乎没有区分度，
`六级`、`药水` 这种只在两三段里出现的才说了算。这一层是把「召回一堆有点像的」收成
「按相关度排好的几条」的关键。

### 注入

`envPromptVars()` 返回 `memory.recall`，模板里就是这段：

```
## 相关记忆（自动检索，可能不全）
- [[notes/pwa-run-state.md]] …这局的药水只有敏捷药水，血 47/80…（2026-10-30）
```

- 条数 `topK`（默认 5），**总量硬上限 2000 token**；
- 同一批记忆**连续两轮不重复注入**；换了话题（query 变了）才重置；
- query 取法：最近 2 条「人说的话」（事件库里 `origin=external` 的最近消息）+
  `queryHint`；没有新消息时退到最近改动的文件名；
- 预算到点就先不注，检索在后台跑完，下一条前缀生效——**绝不拖住前缀构建**。

> 注入点在 system 前缀。Coopanion 在会话开始、上下文交接、前缀重载时重建它
> （也就是 handoff 落地的那个位置），所以不是每一条消息都重新检索。会话中间要立刻翻东西，
> 让模型自己 `memory_search` ——环境提示词里已经写了「想不起细节就先搜，别猜」。

### 事实条目

```yaml
---
updated: 2026-10-30
status: active          # active | unfinished | superseded | archived
supersedes: notes/old-potion-rule.md
tags: [sts2, potion]
---
```

- 默认只回 `active` / `unfinished`；`archived` 永不返回；`superseded` 要用
  `memory_search(status: "superseded")` 才翻得出来。
- 新条目写 `supersedes`，旧条目**自动**变 `superseded` 并记下 `supersededBy`，
  不用手改两份。这条是 spec「他改主意了不该变成两条打架的记忆」的机械保障。

## 工具

| 工具 | 参数 | 干什么 |
|---|---|---|
| `memory_search` | `query`（必填）、`k`、`status`、`maxAgeDays`、`path` | 检索，回 `{path,title,snippet,score,status,updated}` |
| `memory_index` | `reset` | 增量重建；`reset:true` 从头建 |
| `memory_status` | — | 引擎、目录、规模、上一轮注入、上次扫描 |

## 配置

`worlds.memory.*`，面板上都能改（`workspace` / `embedModel` 改了要重启）：

| 键 | 默认 | 说明 |
|---|---|---|
| `workspace` | `<部署>/workspace` | 索引哪个目录 |
| `indexPath` | `<workspace>/.index/memory.db` | 索引文件 |
| `inject` | true | 关掉后只能手动搜 |
| `topK` | 5 | 每轮注入几条 |
| `budgetTokens` | 2000 | 注入 token 硬上限 |
| `minCoverage` | 0.12 | 低于它的候选不进前缀 |
| `halfLifeDays` | 90 | 时间衰减半衰期；0 = 不衰减 |
| `refBoost` | 0.3 | 30 天内每次引用的加成 |
| `maxAgeDays` | 0 | 只搜这么多天内改过的 |
| `vector` | auto | `off` = 只用全文 |
| `embedModel` | 空 | ONNX 模型目录（可选） |
| `scanSeconds` | 30 | 后台扫描间隔 |
| `skipDirs` | 见上 | 逗号分隔 |
| `queryHint` | 空 | 钉一个当前话题词，拼进自动检索的 query |
| `humanSources` | 空 | 只把这些来源当「人说的话」 |
| `maxChars` | 4000 | 工具回执上限 |
| `chunkMin` / `chunkMax` | 300 / 800 | 分块长度 |
| `maxFileKb` | 2048 | 单篇最大读取量 |

## 实测（真实工作区：99 篇 / 6537 段）

| 项 | 数 |
|---|---|
| 首扫（含向量） | ~3.0 s |
| 单次检索 | 40–90 ms |
| 索引大小 | ~55 MB |
| 一轮注入 | 3 条 ≈ 280 token（上限 2000） |

## 验收（spec 第 4 节）

```powershell
node cortico-world-memory/test/run.mjs          # 90 项，含真实工作区
node cortico-world-memory/test/run.mjs --real   # 真实工作区必须是通的，否则失败
```

对齐 spec 的每一条：

- [x] FTS5 trigram 索引 + `memory_search` 工具 + 每轮自动注入 top-5 + 写文件后增量更新
- [x] 「我上次说的药水还剩几瓶」→ 注入里出现 `notes/pwa-run-state.md` 对应段落，总量 < 2000 token
- [x] `grep` 能找到的，`memory_search` 必须能找到（`敏捷药水` / `不背单词` / `token 上限` 逐个验过）
- [x] frontmatter 过滤（status / supersedes）+ 时间衰减 + 引用计数 + 去重缓存
- [x] 本地向量 + RRF 融合（不接任何云端 API）
- [x] 索引损坏/没建好时静默退回 grep，不报错、不打断对话

## 排错

| 现象 | 看哪里 |
|---|---|
| 面板显示「grep 兜底」 | 这个运行时的 `node:sqlite` 打不开（Electron 44 自带），看面板上的 error |
| 注入一直是空的 | `memory_status` 的 `lastQuery` 是否为空；`docs` 是否为 0；`minCoverage` 是不是卡太高 |
| 改了笔记搜不到 | `worlds.memory.scanSeconds` 等 30 秒，或直接 `memory_index`；也确认没落在 `skipDirs` 里 |
| 索引太大 | 面板「存储」一键清，或调小 `chunkMax` / 加 `skipDirs` |
